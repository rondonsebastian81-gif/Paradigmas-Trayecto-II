Programación Orientada a Objetos (POO)

¿Qué es la Programación Orientada a Objetos?

La Programación Orientada a Objetos (POO) es un paradigma o estilo de programación que nos permite organizar el código de una manera que imita cómo pensamos en el mundo real. En lugar de escribir una lista interminable de instrucciones paso a paso (como una receta de cocina), construimos "objetos" que interactúan entre sí dentro del sistema.

Imagina que estás diseñando un videojuego o un sistema de gestión. Todo lo que ves puede ser un objeto: un usuario, una factura, un botón en la pantalla o un enemigo en el juego. Cada uno de estos objetos tiene características (como su color, nombre o tamaño) y comportamientos (como moverse, calcular un total o enviar un mensaje).

1. Clases y Objetos: El molde y la galleta

Para crear objetos, primero necesitamos un plano o plantilla. A esto le llamamos Clase.

  • Clase: Es el molde. Define qué características y acciones tendrán los objetos que se creen a partir de ella, pero no es el objeto en sí. (Ejemplo: El plano arquitectónico de una casa).
  • Objeto: Es la materialización de esa clase. (Ejemplo: La casa ya construida en la que puedes vivir).

Ejemplo Práctico:

// Definimos la Clase (El Molde)
class Perro {
    constructor(nombre, raza) {
        this.nombre = nombre; // Atributo (Característica)
        this.raza = raza;     // Atributo
    }

    ladrar() { // Método (Comportamiento)
        console.log(this.nombre + " dice: ¡Guau, guau!");
    }
}

// Creamos Objetos (Materialización)
const miPerro = new Perro("Max", "Golden Retriever");
const perroVecino = new Perro("Luna", "Pug");

miPerro.ladrar(); // Salida: Max dice: ¡Guau, guau!

2. Abstracción: Mostrando solo lo importante

La abstracción consiste en ocultar toda la complejidad interna de un objeto y mostrarle al usuario solo lo que necesita para usarlo. Piensa en un televisor: sabes que con el control remoto puedes cambiar de canal o subir el volumen (esa es la interfaz visible). No necesitas saber cómo los circuitos internos procesan la señal para poder ver tu programa favorito.

3. Encapsulamiento: Protegiendo la información

El encapsulamiento agrupa los datos (atributos) y las funciones (métodos) en una sola unidad (la clase), y restringe el acceso directo a algunos de esos datos desde afuera. Esto funciona como un escudo protector para evitar que el código externo modifique el estado de un objeto de manera incorrecta o accidental.

Ejemplo Práctico:

class CuentaBancaria {
    // El símbolo '#' indica que el saldo es privado
    #saldo; 

    constructor(titular, saldoInicial) {
        this.titular = titular;
        this.#saldo = saldoInicial;
    }

    depositar(cantidad) {
        if(cantidad > 0) {
            this.#saldo += cantidad;
        }
    }

    verSaldo() {
        return `El saldo de ${this.titular} es $${this.#saldo}`;
    }
}

const miCuenta = new CuentaBancaria("Sebastián", 100);
miCuenta.depositar(50);

console.log(miCuenta.verSaldo()); // Salida: El saldo de Sebastián es $150

4. Herencia: Reutilizando el código

La herencia permite crear una nueva clase (clase hija) a partir de una clase existente (clase padre). La clase hija hereda todos los atributos y métodos del padre, pero puede tener los suyos propios. Es el principio fundamental para evitar repetir código en la ingeniería de software.

Ejemplo Práctico:

// Clase Padre
class Vehiculo {
    moverse() {
        console.log("El vehículo se está moviendo.");
    }
}

// Clase Hija (Hereda de Vehiculo)
class Coche extends Vehiculo {
    encenderAire() {
        console.log("Aire acondicionado encendido.");
    }
}

const autoDeportivo = new Coche();
autoDeportivo.moverse();      // Heredado de Vehiculo
autoDeportivo.encenderAire(); // Propio de Coche

5. Polimorfismo: Múltiples formas de actuar

Proviene del griego "muchas formas". El polimorfismo permite que objetos de diferentes clases hijas respondan de manera distinta a una misma orden (método) dada por la clase padre. Dependiendo de qué objeto esté recibiendo la orden, el resultado de la acción se adaptará a su naturaleza.

Ejemplo Práctico:

class Animal {
    hacerSonido() {
        console.log("Haciendo un sonido genérico...");
    }
}

class Gato extends Animal {
    hacerSonido() { // Sobrescribe el método del padre
        console.log("Miau, miau");
    }
}

class Vaca extends Animal {
    hacerSonido() { // Sobrescribe el método del padre
        console.log("Muuu, muuu");
    }
}

const miGato = new Gato();
const miVaca = new Vaca();

miGato.hacerSonido(); // Salida: Miau, miau
miVaca.hacerSonido(); // Salida: Muuu, muuu
